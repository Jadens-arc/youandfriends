# 066 — Media pipeline fixture tests

**Phase:** Media pipeline · **Iteration:** one

## Objective

Build the fixture-based test suite that runs the real pipeline end to end against generated audio in every supported format, wired into `release-check`.

## User value

The pipeline keeps working across ffmpeg versions and code changes, verified against real audio rather than mocks.

## Scope

- Generated fixtures: WAV 44.1/16, WAV 48/24, FLAC, MP3, M4A, AIFF, plus mono, silence, very short, and very long cases.
- End-to-end pipeline tests using `InlineDispatcher` — the real pipeline, never a mock.
- Assertions on extracted metadata, loudness within tolerance, derivative playability, and peak determinism.
- A golden-file test for the waveform binary format.
- Wired into `release-check` with a loud skip when ffmpeg is absent.
- A fixture generation script so fixtures are reproducible rather than committed blobs where avoidable.

## Non-scope

- Performance benchmarking.
- Testing against every possible real-world file — fixtures cover classes of behavior, not every file in existence.
- Any real music (T9).

## Implementation notes

- Fixtures are **generated**, not sourced. Synthesized tones at known frequency and amplitude make loudness assertions checkable against a computed expectation rather than a magic number.
- Assert loudness within a tolerance, not exactly — ffmpeg versions differ slightly and an exact assertion produces a brittle test that gets disabled.
- The golden-file waveform test is what catches an accidental format change that would break the client decoder.
- A loud skip when ffmpeg is missing, never a silent pass — same principle as task `052`.
- Keep fixtures small. A few seconds each; the 'very long' case can be a few minutes of generated tone, produced at test time rather than committed.
- These fixtures are shared with the seed (task `027`) — one generation script, two consumers.
- **The encoded formats are this task's to add.** Task `027` produces WAV 44.1/16 and 48/24
  natively and stops there: FLAC, MP3, and M4A need an encoder, and ffmpeg is not a dependency
  until task `064`. `encoderAvailable()` in `packages/db/src/seed/fixtures/audio.ts` returns
  `false` today and is the hook to replace with a real probe.
- **The seed's `storage_objects` rows describe bytes that are in no bucket.** They carry real
  sizes and SHA-256 checksums of tones generated in memory, but nothing was uploaded — object
  storage arrives with task `050`. A test here that treats the presence of the row as evidence
  the object is fetchable will fail confusingly.

## Security/privacy considerations

Fixtures are legally unambiguous generated tones — never user music (T9). The suite runs the real pipeline, which is what makes it evidence rather than decoration.

## Acceptance criteria

- [ ] Fixtures cover every supported format plus mono, silence, very short, and very long.
- [ ] The suite runs the real pipeline end to end via `InlineDispatcher`.
- [ ] Metadata, loudness (within tolerance), derivative playability, and peak determinism are asserted.
- [ ] A golden-file test pins the waveform binary format.
- [ ] The suite is in `release-check` and skips loudly without ffmpeg.
- [ ] Fixtures are generated by a committed script; no large binaries are committed.
- [ ] No real music exists anywhere in the repository.

2. Change the waveform format deliberately and confirm the golden test fails.
