# 066 — Media pipeline fixture tests

**Phase:** Media pipeline · **Iteration:** one

## Objective

Build the fixture-based test suite that runs the real pipeline end to end against generated audio in every supported format, wired into `release-check`.

## User value

The pipeline keeps working across ffmpeg versions and code changes, verified against real audio rather than mocks.

## Scope

- Generated fixtures: WAV 44.1/16, WAV 48/24, FLAC, MP3, M4A, AIFF, plus mono, silence, very short, and very long cases.
- End-to-end pipeline tests using `InlineDispatcher` — the real pipeline, never a mock.
- Assertions on extracted metadata, loudness within tolerance, derivative playability, and peak determinism.
- A golden-file test for the waveform binary format.
- Wired into `release-check` with a loud skip when ffmpeg is absent.
- A fixture generation script so fixtures are reproducible rather than committed blobs where avoidable.

## Non-scope

- Performance benchmarking.
- Testing against every possible real-world file — fixtures cover classes of behavior, not every file in existence.
- Any real music (T9).

## Implementation notes

- Fixtures are **generated**, not sourced. Synthesized tones at known frequency and amplitude make loudness assertions checkable against a computed expectation rather than a magic number.
- Assert loudness within a tolerance, not exactly — ffmpeg versions differ slightly and an exact assertion produces a brittle test that gets disabled.
- The golden-file waveform test is what catches an accidental format change that would break the client decoder.
- A loud skip when ffmpeg is missing, never a silent pass — same principle as task `052`.
- Keep fixtures small. A few seconds each; the 'very long' case can be a few minutes of generated tone, produced at test time rather than committed.
- These fixtures are shared with the seed (task `027`) — one generation script, two consumers.
- **The encoded formats are this task's to add.** Task `027` produces WAV 44.1/16 and 48/24
  natively and stops there: FLAC, MP3, and M4A need an encoder, and ffmpeg is not a dependency
  until task `064`. `encoderAvailable()` in `packages/db/src/seed/fixtures/audio.ts` returns
  `false` today and is the hook to replace with a real probe.
- **The seed's `storage_objects` rows describe bytes that are in no bucket.** They carry real
  sizes and SHA-256 checksums of tones generated in memory, but nothing was uploaded — object
  storage arrives with task `050`. A test here that treats the presence of the row as evidence
  the object is fetchable will fail confusingly.

## Security/privacy considerations

Fixtures are legally unambiguous generated tones — never user music (T9). The suite runs the real pipeline, which is what makes it evidence rather than decoration.

## Acceptance criteria

- [x] Fixtures cover every supported format plus mono, silence, very short, and very long. (`MEDIA_FIXTURES` in `packages/media/src/fixtures/catalog.ts`: WAV 44.1/16 and 48/24, FLAC 48/24, MP3, M4A (AAC), AIFF, mono, digital silence, half a second, and three minutes. A test asserts the catalog keeps covering each class.)
- [x] The suite runs the real pipeline end to end via `InlineDispatcher`. (`apps/jobs/src/__tests__/formats.test.ts`: every fixture goes through `enqueueMediaJob` → `InlineDispatcher` → `processAudioVersion` with real ffmpeg and a real Postgres. It lives in `apps/jobs` rather than `packages/media` because the pipeline writes to the database, which `packages/media` may not import.)
- [x] Metadata, loudness (within tolerance), derivative playability, and peak determinism are asserted. (Codec, sample rate, channels, bit depth and duration per fixture; integrated loudness within ±0.5 LU of the value BS.1770 arithmetic predicts for a 1 kHz tone — `expectedLufs` — and checked to fail when the expectation is moved by 1 LU; `silent` and `too_short` where they apply; the derivative is probed as AAC 44.1 kHz stereo of the right length with `ftyp`, `moov` first; peaks decode, silence is flat, and two runs over the same file give identical bytes.)
- [x] A golden-file test pins the waveform binary format. (`packages/media/src/fixtures/golden/tone-1k-1s.yfwp`, 536 bytes of peaks: decoded, checked field by field, re-encoded to identical bytes, and regenerated from the same tone to identical bytes.)
- [x] The suite is in `release-check` and skips loudly without ffmpeg. (Gate `media fixtures (ffmpeg)`, with a skip reason naming the missing binary; the suites themselves announce `SKIPPING …` through `announceSkip`.)
- [x] Fixtures are generated by a committed script; no large binaries are committed. (`pnpm --filter @youandfriends/media fixtures:generate [dir]` writes the catalog, to a git-ignored `.fixtures/` by default. `du -sh packages/media/src/fixtures` is 32K, the golden peaks file included.)
- [x] No real music exists anywhere in the repository. (Every fixture is a generated sine or silence; `.gitignore` refuses audio extensions.)

**Found by the golden file, and fixed here.** For a track under about 20 seconds, 063's "overview" tier (about 1,000 buckets) was _finer_ than the medium tier and was listed first, breaking the format's coarsest-first order — and a one-second file stored its fine tier twice. The overview is now never finer than the medium tier and is left out when it would equal it; `waveform-format.md` says readers must use the tier table rather than assume three tiers. The 063 test that expected three tiers from a 10-second file was asserting the bug; it now uses 30 seconds and asserts strictly decreasing tier widths, with a separate short-file case.

**Seed.** `encoderAvailable()` in `packages/db/src/seed/fixtures/audio.ts` is now a real probe of ffmpeg's encoders instead of a constant `false`. The seed still writes WAV only — it records rows and uploads nothing — and the catalog here is the canonical list whose WAV rows the seed's two formats match.
