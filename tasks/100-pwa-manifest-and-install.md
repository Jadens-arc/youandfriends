# 100 — PWA manifest, icons, and installability

**Phase:** Mobile and PWA · **Iteration:** one

## Objective

Make You & Friends installable on iPhone: web app manifest, icons, splash screens, theme colors, and a service worker registered with a safe caching strategy.

## User value

An app icon on the Home Screen that opens straight into the workspace.

## Scope

- Web app manifest with the You & Friends name, short name, and theme colors from the Studio Notebook palette.
- Icon set at every required size, plus iOS-specific touch icons and splash screens.
- Service worker registration with a conservative caching strategy for the app shell.
- An install prompt where the platform supports it, and clear iOS instructions where it does not.
- Standalone display mode with correct status bar treatment.
- Versioned service worker updates that do not strand users on stale assets.

## Non-scope

- Offline content caching (deferred `203`).
- Web Push (deferred `210`).
- Background sync — unreliable on iOS; do not claim it.

## Dependencies

`014`, `010`

## Files expected to change

```
apps/web/app/manifest.ts              (typed route, not a static file — see below)
apps/web/public/icons/**              (generated; sources are the two SVGs)
apps/web/public/sw.js                 (static, not app/sw.ts — see below)
apps/web/app/offline/page.tsx
apps/web/app/layout.tsx
apps/web/components/pwa/service-worker.tsx
apps/web/lib/pwa/**
apps/web/proxy.ts                     (/offline must be reachable with no session)
scripts/generate-icons.mjs
package.json                          (pnpm icons)
```

Two deviations from the planned paths, both deliberate:

- **`app/manifest.ts`, not `public/manifest.webmanifest`.** Next's typed route catches a
  misspelled `display` or a malformed icon entry at build time, and a manifest is exactly the
  file whose mistakes surface as "the install button never appeared" on somebody else's phone.
  Next serves it at `/manifest.webmanifest` with `application/manifest+json`.
- **`public/sw.js`, not `app/sw.ts`.** A service worker's scope is its own path, so it has to be
  served from the root as a static file. Under `app/` it would be a route, and a worker
  registered from a route cannot control `/`.

## Implementation notes

- The display name is **You & Friends** with the ampersand. In the manifest JSON it is a plain string; in HTML contexts it must be escaped as `&amp;` (`docs/DESIGN.md` §16).
- iOS ignores much of the standard manifest and needs `apple-touch-icon` links and splash screen meta tags generated per device size. Generate them; do not hand-maintain.
- Cache the app shell only in this task. Caching authorized media without an authorization story is a data-leak risk — offline content is deferred to task `203` deliberately.
- Service worker updates must not strand users. Use a skip-waiting flow with a visible 'new version available' prompt rather than silently serving stale assets for days.
- iOS has no `beforeinstallprompt`. Provide honest Add-to-Home-Screen instructions rather than a button that does nothing (`docs/OPERATIONS.md` §9).

## Security/privacy considerations

A service worker is a powerful interception point. Scope it correctly, never cache authorized API responses or media in this task, and ensure cached shell assets contain no user data. A cached response served to a different user on a shared device would be a serious leak — which is why content caching waits for task `203`'s explicit authorization design.

## Acceptance criteria

- [x] The manifest carries the You & Friends name, correctly escaped in HTML contexts.
      Unescaped in the manifest, which is JSON — `&amp;` there would put five literal characters
      under the Home Screen icon. Asserted both ways, and the built output was read to confirm:
      `{"name":"You & Friends"…}` with `content-type: application/manifest+json`.
- [x] Icons and splash screens exist for all required sizes including iOS-specific ones.
      Thirteen PNGs plus `icon.png` and `apple-icon.png`, generated by `pnpm icons` from two
      SVG sources. A test asserts every path the manifest names actually exists — a manifest
      pointing at a missing icon is rejected wholesale and the install prompt simply never
      appears. Twelve iOS launch images too, at device resolutions, with their
      `apple-touch-startup-image` links generated from the same list — a test asserts the two
      lists are equal, because a device in one and not the other fails silently in both
      directions.
- [x] A service worker registers and caches only app shell assets.
- [x] No authorized API responses or media are cached in this task.
      `/api/` and `/_next/image` are refused, cross-origin is refused, non-GET is refused, and
      the allow-list is two prefixes — so a route added later is uncached by being new. The rule
      is a tested module, and a test also reads `sw.js` to hold the two copies together.
- [x] Install works on supported platforms; iOS gets honest instructions.
      iPadOS is recognised despite reporting itself as a Mac, which is the case that would
      otherwise show an iPad user nothing at all.

1. Add to Home Screen on an iPhone; confirm icon, splash, and standalone launch.
2. Deploy an update and confirm the new-version prompt appears.
3. Inspect Cache Storage and confirm no user content is cached.

## Rollback/compatibility

Additive. Reverting removes installability. A deployed service worker must be unregistered carefully — document the kill-switch procedure in `docs/OPERATIONS.md`.
